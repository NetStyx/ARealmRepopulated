# 0.1.7.0 Changelog

Lets actors hold the game's idle poses, alongside a set of user interface changes and the technical work to support them.

## Functional Changes
- Added a changelog tab to view recent changes
- The actor scale can now be edited in the scenario editor instead of only being displayed
- Actors can now be put into any of the idle poses the change pose command cycles through
- Emotes that seat or lay down an actor can now pick which variant of that pose is used
- The idle action can now be given a duration, holding its pose for that time or indefinitely when no time is set
- Fixed the sit on ground emote not being recognised as a sitting pose
- Added hints to the idle and wait actions explaining what happens when no duration is set
- The stable actor key now holds the whole actor name, and its "Arrp " prefix can be turned off to write a name in any shape that fits.
- Actors can now be given a draw offset, which lifts or shifts their model against the spot they stand on without moving the actor itself
- Character files now bring their advanced skin, hair, eye and lip colours along. The height multiplier is now also correctly imported, so a character saved larger or smaller than its size keeps it.
- Eyewear from a character file is now actually put on the actor instead of only being read from the file

## Technical Changes
- The available poses and the emotes behind them are read from the game data on startup instead of being hardcoded
- Actions no longer store whether they support a duration or a talk line in the scenario file, so changing an action can no longer be overridden by older scenarios
- Emotes and poses are now applied through a single code path
- Removed a leftover condition that treated an animation lock as a looping emote, which no emote uses
- Actor names are written to the game object as UTF-8 instead of one byte per character, which previously mangled anything outside the latin alphabet
- Appearances carry an extended block of continuous colour values plus the model scale, written to the draw object rather than to the customize data. The game allocates those with the model, so they are written after an actor is drawn rather than when it is created
- The shader buffer those colours live in is only written while it reports itself mapped for writing, since writing regardless lands in memory the shader never reads
- Appearances are serialized through options carrying a converter per vector type, because those types expose their components as fields and would otherwise be written out empty and read back as black
- Character file entries are read individually instead of all-or-nothing, and numbers stored as text are parsed with the invariant culture so a comma decimal separator can no longer change their value
- Fixed character files with a partial transparency failing to import entirely
